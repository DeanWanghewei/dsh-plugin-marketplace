# dshm Web 管理后台 + 游客市场页（URL 图库 + 下载统计预埋）

图片模型（按用户澄清）：**插件元数据只存 https 图片 URL 列表** `images: [{url, caption?}]`——GitHub 上传的附件图、RustFS(S3 协议)代理出来的 https 地址、任意 https 图链均可，服务端不经手图片二进制，无需 S3 SDK / 上传接口 / 本地存储。

## 一、后端扩展（packages/server）

### 数据模型（向后兼容迁移）
- `plugins` 表新增列 `images_json TEXT`（JSON 数组，顺序即展示序）——迁移需兼容 MySQL 5.7（无 `ADD COLUMN IF NOT EXISTS`，用 information_schema 检查后 ALTER，幂等执行）；SQLite 走 `ALTER TABLE ... ADD COLUMN` + 捕获重复列错误
- 新表 `download_events(id, at, plugin_id, client, source_type, version)` + 索引（plugin_id, at）

### 新增 API
公开（游客）：
- `POST /api/v1/plugins/:id/report-install` —— 下载计数上报（body `{client:'cli'|'web', version?}`，source 维度取插件 source.type）
- `GET /api/v1/stats/downloads?top=20` —— 下载榜（总数、按插件、按 client/source 维度）
- `GET /api/v1/plugins`、`/plugins/:id` —— 响应增加 `images` 与 `downloads` 字段
管理（Bearer admin）：
- 复用现有 `PUT /api/v1/admin/plugins/:id` 写入 images（schema 扩展后自然支持），`DELETE` 同理——不需要独立图片端点
- 静态资源：`@hono/node-server` 的 serveStatic 发布前端产物，`/` 即市场页（SPA fallback index.html）

### core 同步
- `pluginEntrySchema` 增加可选 `images: [{url, caption?}]`（zod default []，URL 形态校验 https?://）；registry.yaml 可直接带图；`dshm info` 列出图片链接

## 二、前端（packages/web，新建：React 18 + Vite + Ant Design 5 + react-router，中文）

游客（无需登录）：
- `/` 市场页：关键词搜索 + 多分类 chips 筛选 + 插件卡片（名称/描述/分类/verified 徽标/下载次数）+ 分页
- `/p/:id` 详情页：**多效果图轮播（antd Carousel，直接渲染 https URL）** + 完整元数据 + 一键复制 `dshm install ali:xxx` + 安装引导块（`npm i -g dshm-cli`）+ 下载次数；git 源插件前端直连 api.github.com 展示 stars/forks（失败静默降级）

管理（令牌粘贴登录，localStorage 存 Bearer）：
- `/admin` 概览（插件数/下载总量/最近审计）
- 插件管理：列表 + 新建/编辑（四种 source 判别式表单、多分类选择、verified）；**图库编辑 = 增删排序 URL 条目（粘贴 https 地址 + 每图说明，实时预览）**——图源由你自行准备（GitHub 附件或 RustFS 代理，都是 https）
- registry 导入导出（YAML）、令牌管理、审计日志、下载统计页（榜单 + 维度）

## 三、CLI 上报（packages/cli + core）

- `installPlugin` 成功提交后：插件来自 http 型 registry 时 → best-effort `POST /api/v1/plugins/:id/report-install`（client:'cli'，2 秒超时，失败静默）——统计预埋落地：装一次记一次
